## Browser storage, identity recovery and copies

| Storage / copy | Inspected behavior | Future policy/evidence requirement |
|---|---|---|
| Auth session | The app does not override Auth persistence. Installed `firebase_auth_web` 5.15.3 initializes SDK persistence with IndexedDB, browser-local and browser-session alternatives. Sessions are browser/origin-specific; actual selection depends on browser support/settings. | Inspect the final supported browsers' storage and sign-out/expiry behavior; describe session purpose and clearing controls accurately. Do not promise identity transfer across Hosting aliases. |
| App Check / provider storage | reCAPTCHA Enterprise App Check is activated with token auto-refresh. Application code does not inventory the provider's cookies/storage or set a retention promise for them. | Check final Firebase/reCAPTCHA SDK/provider storage, relevant vendor terms and actual browser behavior at the trigger; avoid a blanket “no cookies” claim. |
| Report draft / photo | Draft, location and selected photo are held in application memory; no durable offline-submission queue is implemented. | Do not promise drafts survive reload, browser cleanup or network failure. A camera/gallery original may separately remain on the device. |
| Firestore / public-page cache | Bootstrap disables Firestore disk persistence. Task 5's public repository caches public projections in memory for 60 seconds and explicitly refreshes from the server; this local change does not certify other browsers/copies vanish on withdrawal. | Confirm released behavior; distinguish in-memory SDK/app data from persistent Auth state and HTTP caches. |
| PWA shell / HTTP cache | Custom worker allowlists root/index, manifest and two app icons only; it does not intercept Firebase APIs, tiles, photos or admin data. Standard browser/provider caches and installed app copies remain separate. Private photo response metadata uses `private, no-store`. | Describe the actual released shell/update behavior. Do not equate this allowlist with zero browser storage or guaranteed removal of every prior copy. |
| Exports / public copies | An administrator can download exact CSV; a public viewer can retain an approximate point/date. Removing the server projection cannot erase screenshots, downloads or third-party copies already made. | Decide export recipients, permitted uses, custody/deletion and the response to previously distributed copies. |

Sources: [Bootstrap](../lib/core/services/firebase_bootstrap.dart), [Public repository](../lib/features/map/data/public_incident_repository.dart), [Report controller](../lib/features/report/domain/report_controller.dart), [Shell worker](../web/service-worker.js), [Auth repository](../lib/features/admin/data/auth_repository.dart). SDK persistence was inspected locally; no fresh browser-storage audit was performed.

Loss of the anonymous session through clearing site storage, changing browser/device/origin or losing the device can remove the ability to list/withdraw those reports. The current UI's owner controls do not recover a lost anonymous identity. Google linking attempts to preserve ownership and surfaces conflicts; it is not a guaranteed recovery mechanism or automatic cross-origin migration. Define a separate contact and proportionate proof-of-ownership process before promising recovery, correction or erasure. A claimed incident ID alone must not grant access to private data.

| Dataset / decision | Present behavior or known limit | Owner decision / separate implementation evidence needed |
