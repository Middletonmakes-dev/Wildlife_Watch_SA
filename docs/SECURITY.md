# Security

Firestore denies client writes to private and public collections. Exact reads require custom claims `admin`, role `admin`, or role `analyst`; public reads are limited to the projection collection. Storage object reads require the same trusted role; listings and direct client creates/updates are denied. Exact/admin data never enters the service-worker cache or persistent Firestore cache.

`uploadIncidentPhoto` requires Auth and production App Check, checks incident ownership and the reserved path, bounds Base64 input before decoding, limits decoded input to 2 MiB and JPEG pixel count to 8 megapixels, and uses Sharp to decode/re-encode with metadata removed. A Firestore transaction permanently reserves the processed-image hash before writing. It saves via Admin GCS with generation-zero precondition and no Firebase download-token metadata. This boundary is necessary because Firebase client `putData` can create bearer download tokens that bypass rules. Identical processed-image retries are accepted; different images cannot replace the reserved slot, including after interrupted uploads. The callable returns only success, never a download/signed URL.

The submission callable requires Auth and App Check enforcement, validates finite/ranged coordinates, supported enums, note length, ISO occurrence timestamps, bearing and a stable request ID, rejects forged fields, applies a 5-second per-UID cooldown and uses a deterministic private ID plus canonical payload hash for retry idempotency. Changed payload under an existing request ID is rejected instead of claiming it was saved. The public offset is generated with server cryptographic randomness and retained privately across all moderation statuses.

App Check provider setup and custom claims are manual deployment responsibilities. Only explicit emulator mode may bypass App Check; the Flutter emulator branch requires a demo project. Future abuse work can add stronger device/network limits, anonymous-account-churn protection, duplicate detection, content scanning and retention automation. A valid JPEG is not proof of appropriate wildlife content. Bucket IAM/public access, retention policy, role administration and production App Check behaviour must be reviewed before a pilot.

The actual emulator integration suite tests the trust boundaries; static rule assertions alone are insufficient. At local completion, server SDKs were updated to Firebase Admin 14.5.0 / Functions 7.4.0 and a compatible patched gRPC override. `npm audit` still reports 2 moderate upstream `gaxios`/`uuid` advisories; compatible `npm audit fix` made no change. Do not force a major transitive override without compatibility review. Reassess before any release.
