# Roadmap

## Phase 0 — Repository/Foundation

Exit when the demo starter, typed models, rules, callable boundary, docs and verification run cleanly.

## Phase 1 — Functional reporting MVP

Exit when a pilot Firebase project supports anonymous reports, optional photos, App Check and safe error recovery on representative Android devices.

## Phase 2 — Public map

Exit when accepted server projections, filters, date ranges, attribution and a reviewed tile-provider plan are live without exact-coordinate reads.

## Phase 3 — Admin/data quality

Exit when claims-protected review, duplicate/spam status, counts and safe CSV export are tested with real pilot data.

## Phase 4 — Scarborough pilot

Exit when conservation wording, retention, support contacts, privacy notice and resident feedback are approved by the responsible local stakeholders.

## Phase 5 — Analysis/reporting

Add exports and analysis for road segments, density, live/fatal sightings, time of day and season without prematurely automating hotspot decisions.

Exit when analysts can reproduce a documented crossing/roadkill summary from access-controlled CSV data, including data-quality caveats and methodology.

## Phase 6 — Evaluate expansion

Only after the Scarborough use case is proven should other species, communities or organisations be considered.

Exit when evidence from the pilot supports a separately approved expansion plan with ownership, privacy, cost and maintenance responsibilities; no generic platform is implied.
